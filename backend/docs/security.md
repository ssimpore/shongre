# Shongre Security, Escrow Safety & RLS Specification

## 1. Zero-Trust Architecture

- **Private Secret Isolation**: `SUPABASE_SERVICE_ROLE_KEY`, `STRIPE_SECRET_KEY`, and database connection strings exist exclusively in `backend/` and are never bundled or exposed to frontend code.
- **Architectural Boundary Enforcement**: Automated CI scanner (`backend/scripts/maintenance/check-boundary.js`) rejects any PR or commit introducing server secrets or private backend imports into `frontend/`.

---

## 2. Escrow & Anti-Fraud Safety

1. **Escrow Hold Integrity**: Escrow funds can only be released through authenticated PIN verification or atomic database stored procedures (`release_order_escrow`).
2. **4-Digit Handover PIN**: Hand delivery transactions require the buyer to provide a unique 4-digit PIN generated by database triggers. Senders cannot guess PINs due to rate limiting.
3. **AI Content & Fraud Scoring**: Gemini AI analyzes listing descriptions and prices before publication to flag phishing keywords, prohibited items, or suspicious payment requests (e.g. Western Union).
4. **Comprehensive Audit Logs**: Every privileged operation (moderation, status update, escrow release) writes an immutable record to the `audit_logs` table.
