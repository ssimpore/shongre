# Privacy data inventory

Verified against repository behavior on 2026-08-21. “Collected” means transmitted off-device by an API-mode app; deterministic demo mode stays local except normal development tooling.

| Data                                              | Collection and purpose                                                                 | Destination / recipients                                                 | Linked               | Retention and deletion                                                                                     | Store mapping                                                                      |
| ------------------------------------------------- | -------------------------------------------------------------------------------------- | ------------------------------------------------------------------------ | -------------------- | ---------------------------------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------- |
| Email, user ID                                    | Account creation, login, identity, support                                             | Shongre backend/PostgreSQL; auth infrastructure                          | Yes                  | Account lifetime; email anonymized and credentials removed on deletion, subject to legal holds             | Apple contact info + identifiers; Google personal info + IDs                       |
| Password                                          | Authentication/reauthentication                                                        | TLS to Shongre backend; stored only as salted scrypt verifier            | Yes                  | Credential removed on deletion                                                                             | Not retained as cleartext; disclose security practice, not raw password collection |
| Profile name, seller/business data, phone         | Profile, trust, transaction support when supplied                                      | Shongre backend; verification providers only when explicitly enabled     | Yes                  | Account/transaction requirements; anonymize or retain only lawful records                                  | Contact/personal info                                                              |
| Listing text and attributes                       | Publish and display classifieds                                                        | Shongre backend; public web/app viewers after publication                | Yes/public by choice | Listing lifecycle and moderation retention; remove/anonymize per policy                                    | User content                                                                       |
| Photos/camera output                              | User-selected listing media                                                            | Shongre storage/backend; public viewers after publication                | Yes/public by choice | Listing lifecycle, moderation/legal hold; deletion policy                                                  | Photos/videos, user content                                                        |
| Coarse foreground location                        | Prefill listing location after a user action                                           | Device, then listing backend if user confirms                            | Yes to listing       | Listing lifecycle; removable with listing/account processes                                                | Coarse location                                                                    |
| Messages and attachments                          | Buyer/seller communication, safety                                                     | Shongre backend/storage; conversation participants; moderators on report | Yes                  | Conversation, fraud/dispute/legal retention; account deletion may preserve anonymized transaction evidence | User content                                                                       |
| Reports, blocks, moderation evidence              | User safety and enforcement                                                            | Shongre backend; authorized moderation/support staff                     | Yes                  | Safety/legal retention; blocks can be removed, reports retained by policy                                  | User content / app functionality                                                   |
| Search/favorites                                  | Marketplace functionality                                                              | Shongre backend in API mode                                              | Yes when signed in   | User-controlled/account lifecycle                                                                          | App activity where required                                                        |
| Orders, purchases, delivery/address               | Physical marketplace transactions                                                      | Shongre backend and necessary payment/delivery processors                | Yes                  | Statutory accounting, fraud, disputes, and tax retention may survive deletion                              | Purchases, address, financial information                                          |
| Payment metadata                                  | Payment state; no raw card storage by Shongre clients                                  | Payment processor and Shongre backend                                    | Yes                  | Processor/statutory retention                                                                              | Financial and purchase information                                                 |
| Push token, platform                              | Account-associated notifications                                                       | Expo push service and Shongre backend                                    | Yes                  | Removed on logout/account deletion; rotate on refresh                                                      | Device identifiers / app functionality                                             |
| IP, request/security logs                         | Delivery, abuse prevention, incident response                                          | Hosting/logging infrastructure                                           | Potentially          | Short security/operations retention to be finalized                                                        | Device/other data where applicable                                                 |
| Support data                                      | Resolve user requests                                                                  | Shongre support systems/staff                                            | Yes                  | Ticket and legal retention                                                                                 | User content/contact info                                                          |
| Analytics, ads, tracking                          | **Not collected: no SDK or tracker is enabled**                                        | None                                                                     | N/A                  | N/A                                                                                                        | Do not declare collection unless implementation changes                            |
| Crash diagnostics                                 | **No third-party crash reporter enabled**; OS/store diagnostics may be user-controlled | Apple/Google under their terms                                           | Varies               | Store-controlled                                                                                           | Re-evaluate if a crash SDK is added                                                |
| Contacts, microphone, precise/background location | **Not collected and permissions are blocked**                                          | None                                                                     | N/A                  | N/A                                                                                                        | Not collected                                                                      |

The production privacy owner must fill exact retention periods, subprocessors, international transfers, legal bases, and data-subject contact details before release. Any new SDK or backend processor requires updating this inventory, both store maps, the public privacy policy, and consent/permission flows before collection starts.
