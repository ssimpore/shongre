# Third-party SDK inventory

| Package/capability                                 | Version source                                | Native code               | Data behavior in Shongre                                                          | Privacy/signature action                                                         |
| -------------------------------------------------- | --------------------------------------------- | ------------------------- | --------------------------------------------------------------------------------- | -------------------------------------------------------------------------------- |
| Expo / Expo Router / React Native                  | `mobile/package.json`                         | Yes                       | App runtime and navigation; no independent Shongre tracking configured            | Use supported SDK, run Expo Doctor, inspect release archive manifests/signatures |
| Expo SecureStore                                   | `mobile/package.json`                         | Yes                       | Stores bearer token in Keychain/Keystore; Android backup exclusion generated      | UserDefaults required-reason manifest remains CA92.1; verify archive aggregation |
| Expo Notifications                                 | `mobile/package.json`                         | Yes                       | Device push token sent to Expo push service and Shongre backend only after opt-in | Disclose device identifier/app functionality; verify token cleanup               |
| Expo ImagePicker                                   | `mobile/package.json`                         | Yes                       | User-selected/taken listing photos                                                | Camera/photo purpose strings; no microphone permission                           |
| Expo Location                                      | `mobile/package.json`                         | Yes                       | Coarse foreground location only after user request                                | No background/precise/motion permission                                          |
| Reanimated, Gesture Handler, Screens, Safe Area    | `mobile/package.json`                         | Yes                       | UI/runtime behavior; no intended network collection                               | Inspect embedded manifests/signatures and current upstream advisories            |
| Zod / shared contracts                             | `mobile/package.json`                         | No                        | Local input/response validation                                                   | No store data recipient                                                          |
| Supabase/PostgreSQL                                | Backend only                                  | N/A to app binary         | Shongre storage/auth infrastructure in database mode                              | Contract/DPA, regions, retention, RLS; not a direct mobile SDK                   |
| Stripe                                             | Backend only; mobile purchase UI not enabled  | N/A to current app binary | Physical transaction/payment processing when enabled                              | Processor disclosures and store billing review                                   |
| Google Gemini                                      | Backend integration, demo/disabled by default | N/A to app binary         | Must receive no user data until an explicitly reviewed feature enables it         | Processor terms, minimization, consent/disclosure, both store maps               |
| Analytics, ads, social login, maps, crash reporter | Not installed                                 | No                        | No collection                                                                     | Re-audit before adding                                                           |

Package maintainers and signatures are checked at release time because they change independently of this document. `npm audit` currently reports upstream Expo/Metro toolchain advisories; do not “fix” them by downgrading from the supported Expo SDK. Review reachability and upgrade when a compatible upstream release resolves them.
