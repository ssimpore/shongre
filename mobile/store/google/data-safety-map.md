# Google Play Data Safety map

Candidate mapping; a human must answer the current Play Console form using actual production behavior and processors.

| Data type                                                         | Collected                 | Shared                                                     | Required                                          | Purpose                              | Handling                                                      |
| ----------------------------------------------------------------- | ------------------------- | ---------------------------------------------------------- | ------------------------------------------------- | ------------------------------------ | ------------------------------------------------------------- |
| Name, email, user ID; optional phone/address                      | Yes                       | Service providers as necessary                             | Account fields vary                               | Account, marketplace, support, fraud | TLS in transit; linked; deletion/anonymization process        |
| Photos, listing content, messages, reports                        | Yes                       | Listing viewers/participants by product action; processors | Optional to browse, required for relevant feature | App functionality and safety         | Linked; access controlled; retention/policy required          |
| Coarse location                                                   | Optional                  | Public only if confirmed in listing                        | No                                                | Listing location                     | Foreground only; manual fallback                              |
| Purchase/order/payment metadata                                   | Feature-dependent         | Payment/delivery processors                                | For transaction only                              | Purchase, fraud, accounting          | TLS; legal retention may apply; no raw cards stored by client |
| Search/favorites                                                  | Feature-dependent         | No sale; processors only                                   | No                                                | Personalization/app functionality    | Linked when signed in                                         |
| Device/push token                                                 | After notification opt-in | Expo push service                                          | No                                                | Notifications                        | Removed on logout/deletion, rotated                           |
| IP/security logs                                                  | Yes at server edge        | Hosting/security processors                                | Operational                                       | Security, fraud, diagnostics         | Retention to be finalized                                     |
| Analytics, ads, contacts, microphone, precise/background location | No                        | No                                                         | No                                                | N/A                                  | Not implemented/permissions blocked                           |

Google “shared” definitions and service-provider exceptions must be re-evaluated, not assumed. Confirm encryption, deletion request mechanisms, retention, security practices, independent review claims, and every SDK’s behavior. Update before enabling Stripe/mobile payment UI, AI, analytics, crash reporting, ads, maps, or social login.
